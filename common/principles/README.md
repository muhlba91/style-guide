# Principles

Cross-language rules. A rule that holds in several languages lives here once. Language files in `../languages/` contain only deltas.

## Rule Format

```text
## <ID> · <must|prefer|lean> · <common|language name> · <stated|observed|open>

- Rule / Why / Good / Bad / Source / Check
```

- `must`: stated by the owner, or consistent in the owner's Tier 1 baseline across repos and years. Never combined with `open`.
- `prefer`: the usual choice.
- `lean`: a tendency; single source, AI-era only or email only.
- `stated`: the owner said it directly. Overrides contrary evidence.
- `observed`: derived from the owner's commits and text.
- `open`: the owner must decide. The default is the better-supported option; see the OQ entry in `../../OPEN-QUESTIONS.md`.
- `Check: tool:<name>` means a configured tool in the owner's repos enforces the rule. `judgment` may name a tool that only helps. `judgment` means a human or agent must decide.

## New Repository Checklist (Starting Point, Not a Rule)

Default files of a new repository. A soft guideline: add what the repo type or language needs, leave out what does not apply, and note nothing when a file is left out.

- `README.md` in the skeleton of its repo type, `LICENSE`, `.gitignore`.
- `AGENTS.md` as the tool-neutral agent entry, `CLAUDE.md` linking to it where Claude Code is used, `llms.txt`.
- `mise.toml` and `mise.lock` with every tool pinned.
- `Makefile` with `help`, `check`, `lint` and `test` targets.
- `.pre-commit-config.yaml` and `.conform.yaml`, with the same gates repeated in CI, the secret scan (gitleaks) included.
- Linter configs: `.markdownlint.yaml`, `.yamllint.yml` and the language's own (`.golangci.yml`, ruff, shellcheck).
- `renovate.json`.
- `.github/CODEOWNERS` and `.github/workflows/` with the verify or PR workflow, dependency review, Scorecard and CodeQL.
- Libraries and published images only: the release-please config and release workflow, with `CHANGELOG.md` generated by release-please.

## Avoid (AI-Era Artifacts)

AI-era artifacts to avoid. Material from 2026 that was written with AI help and contradicts the stated preferences. Do not copy it, and remove it in review.

- Long documents and READMEs that grow with every change.
- Banners, box-drawing characters, emoji, status symbols.
- Em dashes.
- `Args:` and `Returns:` docblocks.
- Long file headers and doc comments on every private method.
- Restating the diff in a commit or PR body.
